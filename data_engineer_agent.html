Core Architecture

APEX is a compiler, not an ETL tool. Business logic lives in metadata, not code. Generated artifacts are deterministic.

⚡
The Compiler Principle
Traditional ETL hardcodes business logic in Python DAGs. APEX stores everything in PostgreSQL metadata tables (13 DDL files). Generated DAGs are thin wrappers that fetch config at runtime. Same DAG file, different behavior based on metadata.

End-to-End Data Flow

Complete Pipeline Flow
## DESIGN TIME (Agent generates artifacts) User Input (UI / NL / DTSX) ↓ InputDispatcher → routes to UIInputNormalizer | NLInputNormalizer | DTSXNormalizer ↓ PipelineMetadata (canonical model — all 3 modes produce identical structure) ↓ RegistryManager → selects P01-P09 pattern (or LLM creates new) ↓ APEXDAGGenerator → renders Jinja2 template → Python DAG file ↓ Validator → syntax + imports + security scan ↓ Human Approval (required for PROD) ↓ Git Deploy → feature branch → PR → CI/CD → Airflow ## RUNTIME (Airflow executes generated DAG) Airflow Scheduler triggers DAG ↓ initialize_execution → create pipeline_execution record ↓ wait_upstream (ExternalTaskSensor for cross-DAG dependencies) ↓ raw_to_bronze (PySpark) → ingest, type cast, audit columns, DLQ ↓ bronze_schema_validation (Great Expectations) → PASS/FAIL branch ↓ bronze_to_silver (PySpark) → clean, transform, PII detect + mask, dedup ↓ silver_semantic_validation (Great Expectations) → business rules ↓ silver_to_gold (PySpark) → joins, aggregations, SCD2, surrogate keys ↓ run_quality_checks → weighted score (0–100) ↓ finalize_execution → metrics, lineage, catalog registration, notifications

Three Input Modes

Choose how you define your pipeline. All three normalizers produce the identical canonical PipelineMetadata object.

📝
Mode 1: UI Structured
Fill a comprehensive form via UnifiedPipelineForm. Direct 1:1 mapping to metadata. No LLM required.
  • 9 form sections (identity, source, schema, target, joins, etc.)
  • 70+ source type picker with 9 categories
  • Dynamic forms based on source type
  • Pattern auto-recommendation
  • Type-safe validation at every step
🤖
Mode 2: Natural Language
Describe in plain English. LLM converts to structured config. User must preview and approve before execution.
  • LLM-powered NL → structured conversion
  • Join extraction with fuzzy catalog matching
  • Transform intent detection (9 types)
  • Confidence scoring (>80% required)
  • NL is NEVER executed directly
📦
Mode 3: DTSX Migration
Upload SSIS .dtsx packages. Parser extracts connections, data flows, and T-SQL transformations automatically.
  • XML parser for SSIS packages
  • OLEDB/ADO.NET → JDBC mapping
  • T-SQL → PySpark conversion
  • Variable & expression translation
  • Auto-selects P04 (Legacy Migration) pattern
✔
Normalizer Architecture
InputDispatcher routes input to the correct normalizer: UIInputNormalizer (direct mapping), NLInputNormalizer (LLM-powered), or DTSXNormalizer (XML parsing). All three produce identical PipelineMetadata. The rest of the workflow is uniform.

LangGraph 9-Node Workflow

An explicit state machine orchestrated by apex_workflow.py — not a ReAct loop. Each node has a clear purpose and produces typed output.

NODE 1
normalize_input
Routes to UIInputNormalizer, NLInputNormalizer, or DTSXNormalizer via InputDispatcher. LLM if NL mode.
NODE 2
resolve_pattern
RegistryManager selects P01-P09 from registry.json. Priority: explicit → contract → source type → P01 default. LLM if no match.
NODE 3
load_metadata
Loads feed config, data contract, validation rules, join dependencies, pipeline dependencies from PostgreSQL.
NODE 4
generate_artifacts
APEXDAGGenerator renders Jinja2 template → Python DAG + BigQuery security DDL (if PII detected). Output: dags/generated/{dag_id}.py
NODE 5
validate_artifacts
Python syntax check (compile), required imports, DAG ID in code, no hardcoded secrets, pattern-specific variable presence.
NODE 6
persist_metadata
Save pipeline_execution record (with auto-incrementing sequence) and agent_decision_log audit trail to PostgreSQL.
NODE 7
await_approval
PROD or schema_change only — publishes pipeline.requires_approval to Kafka. PAUSE Resumes on pipeline.approved.
NODE 8
deploy_artifacts
Git: create feature branch → commit DAG + metadata SQL → push → create PR → CI/CD validates (DagBag import test).
NODE 9
handle_error
Cleanup, log error to error_log, notify via email/Slack. Graceful failure with full audit trail.
apex_workflow.py — StateGraph Definition
from langgraph.graph import StateGraph graph = StateGraph(AgentState) # Add nodes graph.add_node("normalize_input", normalize_input) graph.add_node("resolve_pattern", resolve_pattern) graph.add_node("load_metadata", load_metadata) graph.add_node("generate_artifacts", generate_artifacts) graph.add_node("validate_artifacts", validate_artifacts) graph.add_node("persist_metadata", persist_metadata) graph.add_node("await_approval", await_approval) graph.add_node("deploy_artifacts", deploy_artifacts) graph.add_node("handle_error", handle_error) # Linear flow with error branching at each step graph.set_entry_point("normalize_input") graph.add_conditional_edges("validate_artifacts", lambda s: "persist_metadata" if s["validation_passed"] else "handle_error") graph.add_conditional_edges("persist_metadata", lambda s: "await_approval" if s["requires_approval"] else "deploy_artifacts")

Pattern Selection Decision Tree

1. Check Explicit pattern_code
If user explicitly set P01-P09 in the form → Use that pattern directly
2. Check Contract Type Mapping
SCD2 contract → P07 | DATA_VAULT contract → P08 | STAR_SCHEMA contract → P09
3. Check Source Type Mapping
FILE → P01/P02 (by size) | DATABASE → P03 | STREAMING → P05 | API → P06 | LEGACY → P04
4. Default → P01 (File Medallion)
Fallback when no mapping matches. If truly novel, LLM generates a new template (P10+) — always requires human approval.

Where LLM is Used (5 Points)

The LLM powers specific conversion tasks. It never directly executes code or deploys artifacts.

🧠
LLM Safety Principle
The LLM never executes natural language directly. All NL input is converted to structured metadata, validated, and shown to the user for approval before any code generation or deployment.
🗣
1. Natural Language → Structured Config
When user selects NL input mode, NLInputNormalizer uses the LLM to convert free-text to structured PipelineMetadata.
Component: NLInputNormalizer → NLTransformProcessor
Input: "Create a daily pipeline to ingest sales CSV from GCS, join with customers"
Output: Structured JSON: source_type=file_csv, schema, joins, target_zone=gold
Safety: User must preview and approve. Confidence > 80% required.
🔗
2. Join Intent Extraction from NL
When NL mentions joins, the LLM extracts table names (fuzzy matching against data catalog), join keys, and types.
Function: NLTransformProcessor._extract_join_config()
Input: "join orders with customers on customer_id, keep all orders"
Extracts: right_table: "silver.customer_master", join_key: "customer_id", join_type: "LEFT"
Matching: Fuzzy match against catalog_repository.search_assets()
📦
3. DTSX Transformation Mapping
For complex SSIS transformations, the LLM maps T-SQL expressions to PySpark code within the DTSXNormalizer.
Component: DTSXNormalizer + dtsx_parser.py
Input: SSIS Derived Column with T-SQL expression
Output: Equivalent PySpark transformation rule
Fallback: Flags uncertain mappings for manual review
🎯
4. Template Selection Reasoning (Edge Cases)
When source type doesn't clearly map to a pattern, the LLM provides reasoning for selection.
Trigger: Ambiguous source type or conflicting requirements in resolve_pattern node
Output: Pattern recommendation with confidence score
Rule: Confidence < 80% routes to human review
⚡
5. Dynamic Template Creation (No Registry Match)
When no existing P01-P09 template matches, the LLM generates a new Jinja2 template based on similar patterns.
Trigger: RegistryManager returns no match (rare)
Process: Find similar templates → LLM generates new Jinja2 → Validate syntax + security scan → Human approval required
Reuse: Approved templates become P10+ in registry for future use — no LLM needed again
⚠
Where LLM is NOT Used
✗ Direct code execution — All generated code goes through validation
✗ Schema inference in production — Schemas must be explicit (schema_version table)
✗ Security operations — Credentials from GCP Secret Manager only
✗ Deployment decisions — Humans approve production deployments
✗ Runtime processing — Spark jobs read config from PostgreSQL, not LLM

Governance, Security & Data Quality

Enterprise-grade governance built into every pipeline run.

🕵
PII Detection & Masking
Automatic PII detection in bronze_to_silver.py via regex + column name indicators. Detects SSN, credit card (Luhn), email, phone, IP. Persists to data_classification table. Masking strategies: REDACT, HASH, TOKENIZE, PARTIAL_MASK, ENCRYPT, NULL, FAKE. Masking enforced in both Silver and Gold zones.
📋
Schema Evolution
Three drift policies: STRICT (fail on any change), ADDITIVE (allow new columns), FLEXIBLE (allow all, log warnings). Detected in raw_to_bronze.py by comparing incoming DataFrame against schema_version table.
📈
Data Drift Detection
4 drift types: Schema (columns changed), Statistical (distribution shift > 3σ), Volume (row count anomaly > 50%), Freshness (late data > 3h). Results stored in observability_metrics with 30-day rolling baseline.
✅
Great Expectations Validation
Two validation gates: Bronze (column presence, not-null, PK uniqueness, data types) and Silver (business rules, referential integrity, cross-field, range checks). Results to ge_validation_result. BranchPythonOperator routes PASS/FAIL.
🔗
Data Lineage & OpenLineage
Automatic lineage tracking: source → Bronze → Silver → Gold. Stored in data_lineage table. Also emits OpenLineage spec 2.0 JSON to Marquez/DataHub/file via openlineage_emitter.py.
💰
Cost Optimization
Preemptible workers (default 60%), autoscaling policies, GCP billing labels, Dataproc serverless option, CMEK encryption, private subnet networking. Cost tracked in execution_cost_log.
🔨
Self-Healing (VIGIL Pattern)
8 automatic remediation actions: retry with backoff, scale cluster, repartition, reduce batch size, skip corrupt records, switch to full load, clear cache, quarantine + continue. Circuit breaker prevents cascading failures.
📚
Data Catalog & Products
Auto-registration of assets after each zone transition. Full-text search (GIN index). Business glossary with terms & definitions. Data Products registry with subscription workflow (Data Mesh). Tag taxonomy: SENSITIVITY, DOMAIN, QUALITY, COMPLIANCE.
🚀
Multi-Environment Promotion
Environments: dev, staging, prod (via APEX_ENVIRONMENT). Promotion script: promote_pipeline.py --from dev --to staging. Regenerates artifacts with env-specific GCS/BQ paths. Prod requires human approval.

🔨 Common Fixes

IssueSymptomFix
Git Authfatal: could not read UsernameEmbed token: https://x-access-token:{token}@github.com/
Missing domain'domain' is undefinedAdd context alias: context["domain"] = config.domain_id
Python boolsNameError: name 'false'Jinja2 renders false not False; use filters
Docker cacheCode changes not appliedBuild with --no-cache flag
Registry missingregistry_json_not_foundAdd to Dockerfile: COPY registry.json ./
